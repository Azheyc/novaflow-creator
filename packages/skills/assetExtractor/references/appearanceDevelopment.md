# 外观信息判断、补全与差异复核 1.5.0

在人物与独立道具筛选、身份归并后，组装资产图提示词前执行。本规范配合 `characterBoard.md`、`propBoard.md`、`continuityWorkflow.md` 使用；展示布局和无头规则继续由对应规范控制。

## 1. 先读原文，再判定外观是否足够

逐个资产回查指定范围内的全部相关描述，包括首次出场、后续补充、他人观察、换装、伤势、物品操作与破损。记录逐项引文与来源，区分客观外观、角色自述/传闻、比喻与暂时状态。别名先归并，再汇总描述，不能只用人物名、职业、性格或道具名称推导形象。

为每个人物、每件独立道具记录外观描述覆盖：

- `sufficient`：已有信息足以形成具体可画的外观并辨识身份/物件；不要求每一可选细节齐全。
- `partial`：有部分外貌或结构信息，但缺少影响资产制作或人物区分的关键内容。仅有衣服、年龄、帅气/漂亮、气质或职业通常属于此类，不能视为脸部与身体已完整。
- `absent`：在已读范围没有可用的可见外观描述。它不等于整本书不存在，未读范围不得下结论。

人物检查：已知年龄阶段、脸型与颅面骨相、眉眼/鼻/唇/下颌等可见结构、肤色与已知标记、身体轮廓与肩宽/躯干/四肢比例、发型、服装、装备。记录实际已知项，不机械凑齐维度。非人角色按真实头部和身体结构适配。

道具检查：准确品类与时代/世界观、整体剪影和长宽厚比例、构成零件与连接、主要材料和表面、配色、尺寸或可信相对尺度、识别纹样/铭文、使用与开合方式、正反面、当前破损/磨损状态。动作可支持结构约束，但不能由“能打开”自行认定具体铰链型号或内部机构。

原文足够时仅归纳、消歧和转写成可见画面语言，保留所有已知限制和证据。原文明确而相互矛盾的描述先列问题，不靠设计抹平。已经提供相关设定时直接使用，不重复问。

## 2. 缺失时集中问一次，明确不补充后直接设计

初扫与外观汇总后，把同批关键缺项集中展示，可与无头/有头模式询问合并，两个决定分别记录。询问示例：

“这些人物/道具在原文中的外观信息不够：……。你可以补充人物的脸部、身材比例、发型服装或参考图，道具的形制、材质、配色、尺寸/比例和关键结构；也可以说‘没有补充，按故事帮我设计’，我会保留原文已有描述，只补缺项，并区分不同角色。若只想严格提取，也可以保留未知项。”

执行分支：

1. 用户补充：把用户设定登记为独立依据，合并原文并核对冲突；只在仍阻碍制作时追问具体冲突。
2. 用户明确说“没有”“不提供”“你来设计”“直接生成”且语境明确授予外观补全：当轮直接为缺项创造、优化、形成完整提示词，不再逐项索取设计许可。只完成范围内的资产外观，不新增剧情、身份、关系或功能。
3. 用户已经提前授权AI设计：跳过重复询问，直接使用授权范围。用户明确只给部分设定且委托其余自由设计时同样适用。
4. 用户沉默尚未回答、回复含糊、没有交互返回或时间经过：保持 `awaiting_user`，不能当作“不提供”或设计授权。可以继续事实扫描，不输出伪定稿外观。
5. 用户选择只严格提取或拒绝AI补全：使用 `strict_unresolved`，保留未知项/必要占位符并标记draft，不强制设计。

外观设计授权与无头/有头选择互不替代。无头模式未确认时仍等待，不因授权设计自动选择人物模式。

## 3. 设计只填空白，事实与方案分层

原文事实保存在facts并绑定证据。用户补充登记来源。AI补全写入proposals，逐项写field、value、origin=ai_design、basis、authorization_basis、status=proposed或accepted；AI设计不伪造原文引文，不填入facts。原文未交代的事实仍可留在unknowns，同时注明本次制作已有哪条设计解决该缺项。

按时代、世界观、明确身份、生活环境和功能需求设计合理形象；性格与职业只能是美术方向，不能直接当作必然的脸型、肤色、缺损或体型事实。只补获授权的缺项，不为差异化改掉原文年龄、亲缘、身体能力、指定外貌、同款装备或关键剧情道具结构。

用户授权“帮我设计”已经允许直接交付完整候选提示词，无需逐个细节再确认。标明“AI设计方案，供采用/修改”，不是“原著定稿”。设计方案可有完整可用提示词（prompt_status=ready仅表示输入完整），核心设计仍保留proposed直到用户采纳；阻碍生成的身份冲突、信息未解决时为draft。

不要把同一份泛化外貌句子复制给不同角色，也不把面部、身体占位符原样充作完整提示词。有依据的微观材质和获授权设计材质可具体描述。

## 4. 人物逐个设计，全体横向复核

每个母角色先建立可独立复用的视觉识别摘要：

- `face`：具体脸型/颅面轮廓，结合有区分度的眉眼、鼻、嘴、下颌等结构；稳定特征须与原文/用户设定或AI方案对应。
- `body`：可见身体轮廓、肩背与躯干宽窄、四肢相对比例、肌肉/脂肪分布或非人形体结构。使用自然、克制且适龄的描述，不靠服装颜色代替体态。

不同角色默认在脸部和身体轮廓两方面都能辨识：近似年龄、统一画风、同制服也不能仅改名字和衣服。设计空间允许时，脸部选择至少两项相互配合的可见结构区别，身体选择至少一项合理轮廓/比例区别；这是美术检查目标，不是凑特征的硬性数值配额，更不允许违背原文。缺少设计权或原文明示相同而与差异目标冲突时先澄清，不能擅自改事实。

建立“角色编号｜原文/用户锁定项｜脸部识别摘要｜身体轮廓摘要｜与最相近角色的具体区别｜设计来源”对照表，先查同场、同年龄/同服饰的易混角色，再查全体已有角色，包括后续批次；与最新已确认表接续，不重随机设计旧角色。相似度高时只调整未锁定且获授权部分，检查修改是否确实进入最终提示词。

同一角色不同年龄/服装/伤势/形态版本保留可继承身份锚点，仅改变对应状态；已明确变形/易容按剧情记录差异。亲属可有家族相似性，默认仍保留个体区别。明确要求完全相同的脸或体态，必须记录原文明示证据或用户针对具体对象与范围的授权；单纯“兄弟”“双胞胎”称呼不自动授权复制脸和体型，若原文明示同貌则直接保留并记录原文证据例外，不额外要求许可。相同脸/身体范围分别记录，不把只同脸扩成体型也相同。

每条独立可复制人物提示词要完整携带本角色的具体face、body与当期妆造。无头版body进入身份/身体段，face进入右列，发型只按中右列对应范围；有头版按完整正面与正脸保持同一身份。每张板内部的“同一人物”只约束当前母编号的三视图，不能扩展成全体角色共用同一脸与身体。

原生生成每个角色单独提交本角色提示词，不把多角色外貌混入一张单人板。绑定身份图时逐个核对真实路径和角色；画风/构图可以共享，同一张身份参考不能无说明地给多个不同角色锁脸。若平台支持相关设置，只在已确认能力下调整；不编造可用参数，不宣称换随机种子就能保证不同脸。

## 5. 道具先汇总信息，再按品类与实体辨识

每件独立道具按已读信息整理成“剪影—结构—材质—配色—尺度—识别细节—状态”描述，保留其功能约束和正反面依据。原文有描述就具体展开；缺关键结构按第2节问，明确不补充或已授权后才设计。只补外观和合理可见结构，不擅自增加会改变剧情的机关、能力、内部零件或品牌型号。

不同类别、不同制式或原文明示不同的物件应使用各自具体形态，不能一律套同一金属材质/纹样。对同类但需要辨识的关键独立物件，在原文或授权空间内区分剪影、部件比例、柄/盖/扣等结构或局部识别特征，而非只改道具名。

同一物件换持有者和状态版本继续同一基础结构；同型号批量装备、成套物件、配对物或原文相同物件可以共享制式，不强行设计成每件外观不同。编号用于追踪物理个体；无法视觉区分时如实注明，不能凭空加划痕和编号。需要差异且原文锁定相同结构时先问。

## 6. 交付和检查记录

01人物文档追加外观覆盖判断、缺项及询问结果、事实/用户设定/AI设计分层、全体脸部与体态对照表；02道具文档追加逐项信息汇总、缺项决策与必要的同类对照。04文档登记未解决项及例外。

新人物与独立道具presentation增加appearance_development对象（version=1.5.0），结构见 `assetSpec.md`。visual_signature中的短句必须实际进入正向提示词；同图直接包含，拆图按可见范围放置（无头正面携带body，face_detail携带face，背面携带body；道具两全貌都携带可见主体信息）。锁定词与来源保持一致，不把摘要与提示词做成两套设计。

脚本检查字段、部分摘要原文携带和规范化后完全相同的脸/体态文本；只能发现明确重复，不能判断近义词是否同脸或图像是否同人。人工还要核对面部/身体的实际语义差异、事实边界、授权与参考图职责。实际生图后再比较脸型、五官结构和身体剪影；撞脸/同体态则按真实失败部位调整获授权方案并重验，不把文字不同当成图像已不同。
