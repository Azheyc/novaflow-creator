# 身份、状态与连续性补强 1.5.0

## 使用时机

执行实体归并、版本划分、参考图绑定和最终提示词组装时读取本规范。保留主流程的证据、稳定编号和四份文档结构；下列扩展是分析与制作约束，不改变原文内容。外部研究来源见 `researchSources.md`，运行资产提取时无需联网读取来源。

## 四层判断

| 层次 | 判断问题 | 存放位置 |
| --- | --- | --- |
| 身份 | 是否仍为同一个人、同一个物理地点或同一件物品？ | 母资产与稳定编号 |
| 视觉状态 | 身份不变，服装、年龄阶段、形态、伤势、开合、破损、昼夜或天气是否有实际视觉差异？ | 人物/道具 versions，场景 variants |
| 展示视图 | 是否只改变观察方位、镜头高度、画幅与构图？ | presentation，同一资产/状态的展示方案 |
| 场次使用 | 是否只是表情、姿势、视线、站位、持有者、持有手或一次互动变化？ | shots中使用记录与notes；持续影响身体/空间的关系另记有效范围 |

人物稳定外观和当前妆造分层记录；服装换色不创建第二个人，短暂愤怒不创建人物版本。重大持续伤势或形态变化可建版本，原文没给持续性时保留未决。发型如随造型改变归版本，稳定发型有证据时可作为母资产识别特征，不强行预定其层次。

场景固定地理与昼夜/天气状态分开。门窗、主要通道、固定地标之间以物理关系描述；未建立朝向基准时使用“入口对面”“石阶连接平台”等有依据关系。只有选定观察点后才描述画面左/右。同地点换方位仍为同一地点；独立房间或制作区块按主流程判断。

物品外观与剧情用途分开。道具提示词写可见形态和当前状态；持有者、交接与用途在资产卡和场次表维护。两件同款且需独立追踪的物件保留独立编号；同一物件换持有者保留母编号，必要时只更新使用记录。不能仅按同名合并。

## 逐场两轮复核

第一轮按完整场次寻找实体、实际出场、可见外观与变化证据。第二轮围绕候选与既有资产，逐项确认新建、复用、增加版本或保持未决，并检查：

- 明确可见人物是否已关联；群体制式与剧情特指个体是否分清。
- 关键交互物品是否漏记；陈设是否无需独立制作；道具数量由实际需求决定。
- 服装、发型、伤势、开合、破损或昼夜变化是否记在对应状态中。
- 每场使用的是哪一身份与哪一状态；继承关系是否只沿已知故事时间成立。
- 同一场景锚点、入口和通道在相邻场次是否一致；状态变化是否仅改变有证据的部分。

把不确定结论保留在 issues 与 unknowns。完成两轮复核仍不能宣称语义无遗漏。

## 最小稳定锚点与持续关系

每项资产从facts、用户设定及获授权的设计方案中挑选可辨识且适合比较的最小可见特征，作为“稳定识别锚点”，标明对应来源。未说明外貌时先按 `appearanceDevelopment.md` 询问；用户明确不补充并委托AI或已预先授权时，直接设计缺项并保留proposed来源，不伪造事实。全体不同母角色分别检查face与body，单个角色的跨视图一致只作用于本母编号；同一角色版本保持可继承锚点。同款道具允许制式一致，具体实体编号与视觉差异分开管理。

跨场需要维持的稳定事实按其生效范围锁定；会变化的部分留在状态。例如衣服配色属于特定造型的锁定内容，门窗相对位置属于地点母资产。提示词只在对应部位入画且相关时携带锁定内容。字符相同只能证明文字携带，不能证明图像一致。

对持续限制动作的支撑、固定、负重、佩戴或接触关系，记录相关资产、开始场次、结束条件/结束场次与依据。不把持续依托误当一次站姿。只有故事明确改变或时间关系得到确认时才结束/继承；倒叙、梦境、时间跳跃单独复核。

以上可先在04文档与shots.notes中记录，不为文字说明引入未经规范与脚本支持的顶层JSON字段。

## 参考图职责登记

仅在用户提供参考图或已知真实资产图时填写。为每个真实图像建立 reference_bindings 条目，记录：reference_id、path、status、用途 purpose、允许影响 controls、不得自动继承的内容 exclusions。status为provided/available/planned；planned只表示计划，不代表已有图片或已经绑定模型。

purpose从 identity、look_state、geometry、composition、scale、material、style 中选一项。单张图片有多项职责时分成不同绑定条目并引用同一路径，避免权重与职责含混。编号分配后保持语义稳定，上传顺序另记；更换路径要说明变更，不能暗中复用编号指向另一身份。

身份参考负责脸、体态等已确认身份特征；造型参考负责当前衣服、发型与装备状态；几何参考负责已知地理或结构；构图参考只负责视图关系；风格参考只负责画风与材质呈现。每条controls与exclusions写实际范围，不使用泛化空话。图中偶然出现的人物、文字、背景、配色与物件不因引用图片就自动成为剧本事实。

reference_bindings放在具体presentation内；关键参考缺失或planned且决定外观时列pending_fields并保持draft。未提供参考图时可省略，继续原生文生图。

## 版本展开与局部修改

为每个实质视觉版本记录基础、差异、保留项、生效范围与证据。母资产外观与版本差异在数据中分层存储，原文与获授权AI方案分别追踪；可复制提示词则展开为“基础外观及本次可用方案＋当前版本差异＋本类展示构图”，保证独立粘贴可用。差异覆盖同一字段时使用当前版本值，不把两个互斥状态并列；无法判断覆盖关系时列问题。

对已有资产做局部修改时，在文档明确四项：目标编号/版本、具体变化、必须保留的身份/结构/材质/方位、受影响场次及关联资产。用户锁定或手动确认的部分优先保留；修改触及身份、地理或重要状态时先更新对应资产定义，再同步必要引用。更新前读取当前文件，核对用户手改，不用旧副本覆盖当前事实。

默认交付新的资产文档，本规范不授权改写输入剧本、覆盖已有图片、修改三维工程或启动生图。
